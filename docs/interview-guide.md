# Technical Interview & Architecture Defense Guide

This document equips engineers and candidates to defend every architectural and algorithmic decision made in PolicyLens AI.

---

### Q1: Why build this as a Modular Monolith in Django rather than Microservices in FastAPI?
**Answer:**
Insurance policy analysis involves tight transactional coupling between documents, pages, chunk embeddings, and extracted clauses. In microservices, coordinating document uploads, OCR extraction, vector indexing, and clause extraction introduces distributed transaction overhead, network latency, and eventual consistency risks. Django provides enterprise-grade ORM abstractions, rock-solid database migration tooling, built-in security middleware (CSRF, XSS, HSTS), and mature Celery integration. By architecting clean bounded contexts (`apps.policies`, `apps.documents`, `apps.clauses`, `apps.ai_engine`), we gain clear microservice-ready code boundaries without the operational tax of distributed systems.

---

### Q2: Why use Celery with Redis for ingestion instead of in-process async (`asyncio`)?
**Answer:**
PDF parsing (PyMuPDF) and OCR (Tesseract) are **CPU-bound** and memory-intensive operations. In Python, executing heavy CPU tasks within an `asyncio` event loop blocks the thread and stops handling incoming HTTP requests. Celery isolates heavy CPU workloads into separate worker processes running in dedicated containers (`policylens_celery_worker`), protecting the web WSGI server (`policylens_backend`) from starving for memory or CPU. Redis serves as an ultra-fast broker and result backend.

### Q3: Why store vectors directly in PostgreSQL using `pgvector` instead of Pinecone or Qdrant?
**Answer:**
1. **Single Source of Truth & ACID Transactions:** If a user deletes a policy, `ON DELETE CASCADE` instantly wipes the policy, its PDF files, its physical pages, and all chunk vectors in one atomic transaction. A standalone vector DB requires two-phase commits or leaves orphaned vector tombstones.
2. **Pre-Filtering with Zero Cross-Tenant Leakage:** pgvector queries execute within standard SQL `WHERE` clauses (`WHERE document__policy_id = :policy_id`). Pinecone or Qdrant require custom metadata namespaces or complex hybrid filters.
3. **Operational Simplicity:** A single robust PostgreSQL instance with automatic backups and replication powers both relational records and semantic vector search.

### Q4: How do you guarantee zero hallucinations in insurance answers?
**Answer:**
Our pipeline implements a **4-tier anti-hallucination defense**:
1. **Evidence Sufficiency Gate:** Before invoking the LLM, the retriever calculates semantic and term scores. If relevant chunks do not meet the minimum threshold ($\ge 0.2$), the system aborts early with *"I couldn't find enough information about this in your policy document."*
2. **Grounded Extraction Prompting:** System prompts constrain the model strictly to the provided document excerpts.
3. **Deterministic `CitationVerifier` Layer:** Every citation generated by the AI is intercepted before being returned to the user. It must resolve to an authentic `DocumentChunk` and `DocumentPage` in PostgreSQL, and the physical page number is checked.
4. **Verbatim Text Injection:** The citation text displayed to the consumer is queried directly from the database—the model's generated text is never displayed as the source quote.

### Q5: How does the system prevent Cross-User Retrieval (IDOR in RAG)?
**Answer:**
Cross-tenant leakage in RAG is a critical flaw where User A's vector query retrieves User B's chunk embeddings. In PolicyLens AI, `PolicyRetriever.retrieve()` explicitly receives the requesting user and policy instance. The query is strictly isolated at the ORM layer:
```python
DocumentChunk.objects.filter(document__policy=policy, document__policy__user=user)
```
If a user attempts to pass another user's policy ID, the request fails with a `404 Not Found` or `PermissionError` before any vector embedding or similarity search occurs.

### Q6: How do you handle external LLM provider failures, rate limits, and latency spikes?
**Answer:**
1. **Exponential Backoff Retries:** Celery tasks catch transient connection/rate-limit exceptions and retry with exponential backoff (`2 ** self.request.retries`).
2. **Provider Abstraction:** The system decouples business logic from providers through `BaseLLMClient` and `BaseEmbeddingClient`. Providers can be swapped seamlessly from Gemini to OpenAI or local models via environment variables (`LLM_PROVIDER`, `EMBEDDING_PROVIDER`).
3. **Safe Status Tracking:** If all retries are exhausted, the policy status transitions cleanly to `FAILED` with a sanitized error message, allowing the user to retry without application crashes.
